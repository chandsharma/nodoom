# Open-source launch plan

Good software is not discovered by README length alone. No Doom needs visible proof, a safe distribution story and repeated community participation.

## Before announcing

- Finish M0 and publish an honest compatibility table.
- Record a 15–25 second portrait video: open one Reel, attempt several swipes, leave, show normal Explore scrolling, tap the Reels tab and return Home.
- Blur usernames and private content; use a test account or public demo material.
- Add a clear social-preview image and a small demo GIF to the README.
- Publish the first signed APK, checksum and signing-certificate fingerprint in GitHub Releases.
- Enable GitHub Discussions, security reporting and issue templates.
- Add the repository topics listed in the README.

## Launch story

Lead with the problem and the one-sentence result:

> I wanted Instagram for friends and messages, not an infinite slot machine. No Doom keeps the official app but makes every Reel a one-Reel experience.

Show the working video before explaining implementation. Emphasise official Instagram, no root, no login, no Internet permission and source availability. State the tested Pixel/Android/Instagram versions prominently.

## Places to share thoughtfully

- Android and digital-minimalism communities where self-promotion is permitted.
- A short “Show HN” post focused on the Android interaction problem and privacy design.
- Developer communities interested in Accessibility, attention-aware design and open source.
- Personal LinkedIn/Mastodon/X posts with the demo video and a direct GitHub link.
- Relevant newsletters and maintainers of curated Android/open-source lists.

Read each community's rules, participate in discussion and avoid cross-post spam. Answer installation and privacy questions quickly; useful support turns early users into contributors.

## Ongoing discovery

- Publish compact release notes with every Instagram compatibility fix.
- Maintain beginner-friendly issues and a compatibility-report template.
- Thank contributors visibly.
- Track stars only as awareness; track successful live checks, false positives and resolved compatibility reports as product quality.
- Never pay for fake stars, reviews or engagement.
